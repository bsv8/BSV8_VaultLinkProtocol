## 4. SDK 来源与版本

| 依赖 | 版本 | 用途 | 来源 |
| --- | --- | --- | --- |
| `bsv8-channel-protocol` | `0.6.0` | Channel public/hash/private 编码、seal/open、错误码 | 外部 npm 包，Keymaster 8 个包引用 |
| `keyhold` | `2.1.0` | KeyHold SDK | 外部 npm 包 |

`bsv8-channel-protocol@0.6.0` 是 **Channel Profile 的规范权威来源**，不是参考实现：
其 scope 字符串（`bsv8.public-message.v1`、`bsv8.private-message.v1`、
`bsv8.inbox.envelope.v1`）、JCS 摘要规则、secp256k1 ECDH（压缩点 X 坐标）、
base64url 编码与 17 个错误码构成 VLP Channel Profile 必须逐字节兼容的目标。

`bsv8-channel-protocol@0.6.0` 的以下事实已核对（VLP 规范引用它们，不重新发明）：

- 公钥：66 字符小写 hex，压缩 secp256k1 点。
- 签名：strict DER 的无填充 base64url，8–72 字节，low-S，且要求规范 DER 重编码一致。
- 消息 ID / 会话 ID：32 字节 → 无填充 base64url（43 字符）。
- 摘要：`SHA256(JCS({scope, channel, from_public_key, message}))`；wire 消息体省略 `channel`。
- 私密信封：ECDH 得压缩点 X 坐标 32 字节 → HKDF-SHA256(salt=32 字节随机 salt，
  info=`JCS({scope:"bsv8.inbox.envelope.v1", channel, from_public_key})`) → AES-256-GCM，
  AAD=`JCS({channel, envelope_version, from_public_key, kdf_salt, nonce})`，
  信封字段 `{channel, envelope_version, from_public_key, kdf_salt, nonce, ciphertext}`。
- 协议子类型寿命上限：Ping/Pong 60 000 ms、WebRTC 120 000 ms、app-message/默认 86 400 000 ms。

### 4.1 主机本地秘密 v3 配方（已核对）

来自 `workerKeySession.ts` + `vaultOperationExecutor.ts` + `crypto.ts`，是 VLP
Local Secret Profile 必须保持兼容的既有配方：

```
ikm   = 32 字节身份私钥（原值，不哈希不编码）
salt  = "keymaster.vault.local-secret.v3"
info  = UTF8(小写压缩公钥 hex, 66) || 0x00 || UTF8(scope)
key   = HKDF-SHA256(ikm, salt, info, L=32)                    → AES-256-GCM 密钥
aad   = UTF8("keymaster:local-secret:v3|" + scope) || 0x00 || salt(16)
seal  = salt=16随机 || nonce=12随机 || AES-GCM(key, nonce, aad, plaintext)，密文含 tag
信封  = { version: 3, keySource: "active-key-hkdf-v1", saltHex, nonceHex, ciphertextHex }
```

关键易错点：**16 字节信封 salt 只出现在 AAD 里，从不作为 HKDF 的 salt**。
Rockey 的 `local_secret.cpp` 与此一致。

### 4.2 主机 P2PKH 配方（已核对）

来自 `p2pkhSigner.ts`：BIP143，`SIGHASH_ALL|SIGHASH_FORKID = 0x41`，legacy sighash 显式拒绝。
金额用 BigInt 编码 u64LE（旧 4 字节截断 bug 已修，>42.95 BSV 正确）。
`scriptCode` 由 UTXO 地址重建为标准 25 字节 P2PKH。
scriptSig = `varint(len(der||0x41)) || der || 0x41 || varint(33) || compressedPub`。

**已记录的行为差异**：`p2pkhTransferService.ts` 的费用求解器在 `prepare` 阶段就调用
`signRawTx` 生成真实可广播签名以测量字节长度。这是 KM-RK-05 明确禁止的
（不能为了估费产生可广播签名）。VLP P2PKH Profile 的「预览不签名」要求会与此冲突，
属接入时必须解决的产品侧问题，见 [0002](./0002-差异清单.md) §5。

## 5. 工具链

| 工具 | 版本 | 用途 |
| --- | --- | --- |
| Node.js | v22.17.0 | 独立参照实现路径 B、AES-256-GCM/X25519/ECDSA 对照 |
| Python | 3.14.0 | 独立参照实现路径 A（`hashlib` 含 ripemd160）、向量生成 |
| OpenSSL | 3.6.0 | 交叉对照（不作为规范依据） |

Python 侧**没有** `cryptography` 与 `cbor2` 包。因此参照实现路径 A 只用标准库
（`hashlib`/`hmac`）覆盖 SHA-256、SHA-256d、HMAC、HKDF、RIPEMD-160、CRC-32；
AES-256-GCM 与 ECDSA 由路径 B（Node）与向量对照承担，两条路径不共享代码。
