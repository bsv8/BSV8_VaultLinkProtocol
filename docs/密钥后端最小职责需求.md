## 1. 三方边界

| 归属 | 当前职责 |
| --- | --- |
| Keymaster | 公钥/交易的用户教育、业务说明、对方身份/信用资料、服务查询与 Markdown 展示、原有业务确认、App 权限、请求构建、网络/存储/广播 |
| 软件密钥后端 | 单 Key 管理、软件解锁/锁定、现有权限及生命周期检查、支持操作核验与密码执行；既有检查通过且支付额度内直接执行，超额按渠道规则确认 |
| RocKey | 单 Key/PIN/封装、受支持操作的独立核验、基础事实显示、实体同意/否决与会话撤权、密码执行、导入/导出/恢复 |
| VLP | 主机与密钥设备之间的共同编码、USB 认证连接、请求/承诺/授权/结果、已支持签名 Profile、迁移契约与 SDK；不标准化信用服务接口或完整业务解释 |

软件“自动同意”仅省去额外人工设备式确认。不能绕过 App 权限、用户已有业务确认、owner/scope、操作有效性、锁定、世代或撤权检查；解锁不等于把私钥能力开放给任意调用者。软件执行失败或锁定仍明确拒绝。

## 2. RocKey 支持集与基础解释

1. 标准 BSV 交易签名：以已有 P2PKH 为首个明确支持集；“标准”不能解释为任意脚本。核对实际输入/前序证据、输出/收款、找零归属、矿工费、网络和 sighash 覆盖范围，设备自行计算签名摘要。
2. 费用池交易签名：作为独立 Profile/解析器施工目标。审计现有 Connect feepool 与 BitFS 的实际用途，按真实脚本、交易阶段和版本分别冻结，不能仅看主机 action 名称。
3. 其他明确登记的签名：身份/意图、Channel、文件声明等按已有需求清单逐项冻结，显示用途、对象、范围及必要风险。不新增任意 signHash/signDigest、通用算法或未知扩展签名入口。
4. 私钥导入、主动导出与恢复：保持同 Key 身份和旧数据；专用状态、PIN 重新认证与物理确认，不对普通 App 开放，不自动擦除唯一可恢复材料。
5. PIN、密钥封装、锁定、失败计数/等待与发布保护；PIN 只在设备输入。

现有 Channel seal/open、本地秘密 v3 等兼容依赖不因边界收窄默默删除，也不因此自动宣称全部已支持；由调用清单列明必需能力与未实现项，无解析器时明确不可用，不回退软件或盲签。

基础解释来自设备解析/核验后的实际操作和本地固定模板，不来自 Keymaster 的信用评价或业务故事。说明“谁”指完整公钥/地址或脚本参与方，不要求设备识别企业/个人昵称。

## 3. 费用池冻结门禁

费用池不是任意多签通行证。实施前必须列出开池/funding、更新累计付款、关闭/结算、退款等实际存在的阶段与协议变体；每类规定真实交易字节、前序输出/outpoint、脚本、双方公钥及顺序、输入金额、网络、签名角色、sighash、sequence/locktime 与必要状态证据。

设备基础摘要按阶段显示池对象、双方、锁入资金、本次与累计支付、余款、矿工费及适用锁定/退款条件；字段无法从当前交易得出时需定义可核验证据，不能直接相信主机累计金额。状态更新签名不等于已广播。预算消耗、序号/状态连续性及重放规则按实际协议冻结；同池与跨池/对端/网络不混用授权。

尚未冻结具体脚本/版本及持久状态方案，不发明 wire 字段、不把当前 P2PKH 解析器当作费用池支持。首版支持哪些实际变体联合决定；未选入项公开不可用。

## 4. 硬件授权与软件执行

Keymaster 完成业务说明、原有确认及权限检查后提交实际操作。软硬后端复核上下文与支付额度；额度内自动执行，超额由软件弹窗/硬件基础摘要实体确认后执行。非支付操作沿用已定义规则。

硬件保留本次允许/拒绝、适用的会话允许/否决以及本地撤销；本次决定不写持续表，持续决定按协议/对象/方向/App 会话/限额隔离。私钥导出和擦除不得持续允许。浏览器不代输 PIN、不代替硬件批准。

固定顶栏保留身份/状态/硬件等待，不新增额度内的软件批准；超额确认及设置按支付渠道需求实施。原有业务确认不再复制成钱包弹窗，不要求软件仿照设备三按钮或长按。

签名完成不等于广播完成；结果未知不自动重发。请求变更、撤权、锁定、后端迁移、设备/Worker 重启或注销后旧授权和迟到结果不能复用。

## 5. 保留 USB 最简基线

一个版本使用固定安全套件；握手后 REQUEST/RESPONSE/EVENT，查询/取消/心跳/锁定/关闭为控制操作，无独立业务 ACK。保留实体配对、Key 持有权、认证加密、序号/重放和会话隔离。

设备单活动业务、Keymaster 有界排队，控制始终可达；当前/最近结果与单调接受水位防重复执行，淘汰旧结果不解除防重放，旧结果不可确定不伪称未执行。持久迁移 journal 独立。不再增加信用查询 EVENT、说明密文续传、服务信任根或专用回复解密密钥。

hostContextId 合并仅在上下文变化必断旧连接并撤权时采用；产品内部世代保留。交易容量决定是否需要有界分片，信用长文不再构成设备帧容量需求。套件/握手/AAD 的规范字节仍需冻结验证；逻辑消融不是物理实验或安全审计证据。

## 6. 外部信息归 Keymaster

信用接口继续可采用请求语言/自由文本及 Markdown 回复，允许为空；来源校验、对象/操作绑定、语言、错误和显示安全由 Keymaster 负责。此接口不经 VLP、不交 RocKey 解密、不要求设备拥有信用服务信任根。

撤销“仅设备可以解密外部正文”的要求；不据此替信用服务选定新的算法、传输加密或认证方案。其实现按 Keymaster 业务契约冻结，服务认证与查询隐私需求在主机范围内决定。空正文不代表安全；来源可信不代表操作安全。
