## 1. 名称、目标与首批实现

项目名称为 **BSV8 VaultLink Protocol**，协议简称 **VLP**，中文说明为「密钥设备互操作协议」。仓库名为 `BSV8_VaultLinkProtocol`。下文 SDK 包名为拟定名称，注册可用性尚未核查，不代表已发布。

目标：应用提交规范化业务操作，设备核验操作与授权，向用户展示含义及风险，再返回可关联、可验证的执行结果。应用不通过正式身份 Key 的任意摘要签名接口绕过业务语义。

Keymaster 与 Rockey 是第一组参考接入方，不是协议固有依赖。首版以当前唯一 secp256k1 业务 Key 为基线，不增加钱包列表、多 Key 管理或密钥派生路径体系。设备解锁与软件解锁提供等价业务能力；未支持操作必须明确拒绝。

迁移保持原业务 Key、公钥和既有数据密码学兼容。同 Key 迁移与不同 Key 替换是不同生命周期：前者保留身份与数据，推进后端及会话世代；后者在 Keymaster 注销并删除旧钱包数据后创建/导入。VLP 提供绑定和失效契约，数据库删除由产品执行。

Keymaster 是浏览器身份、App 权限、会话及存储权威；Rockey 是私钥执行及设备物理授权权威。两端权限均须成立。USB 不证明 App origin、设备厂商或交易安全；主机名称、域名和 verified 声明不能升级为设备验证事实。

软件后端属于 Keymaster；无需为了统一 Vault，强制软件 Worker 使用 USB 协议。Vault 统一业务操作，硬件后端通过 VLP 映射这些操作。

首版定义 USB Serial/Web Serial 适配，不增加 HID、BLE、网络或 FIDO/CTAP2。Core 与字节传输解耦，未来传输独立规格、能力和验收，不默认为已支持。

## 3. 规范权威、版本和交付

VLP 规范进入本仓库并联合冻结后，本仓库是共同协议的唯一维护入口。迁移前 Rockey 文档和源码仅作为审计输入，发现矛盾列入差异清单，不把某次实现错误或暂定密码学方案升级为标准。两端旧共同文档在各自接入任务中改为引用，不同时维护第二份规范。

规范、schema、公开向量、SDK 和兼容性工具分别交付。规范是行为权威，参考 SDK 不能以自身输出证明自身正确。冻结产物具有版本及哈希，两端固定消费，不运行时追踪最新分支。

Core、传输、安全套件、Profile 和 SDK 的版本分别标识；兼容矩阵说明可组合版本。未知关键字段、操作或版本拒绝，不静默降级。能力声明绑定 Profile 版本、支持的操作/格式/限额和授权方式，不宣称未能执行或未通过测试的能力。

先交付 0.1 Draft；冻结候选和正式版本有独立证据，不把源码存在或 SDK 能编译等同于标准完成。首个正式版本不得靠未完成扩展阻止基础能力使用，但必须公开支持集和不支持集。

## 5. Core 契约

### 5.1 身份和世代

业务 Key、USB 临时密钥、方向通信密钥、设备内部 PIN 封装密钥分别命名，不混用。PIN 在设备输入，不进 VLP；普通操作不导出业务私钥或长期派生密钥。

规范定义 identity/publicKey、deviceRunId、connectionId、hostRunGeneration、walletGeneration、backendGeneration、sessionId/sessionEpoch、requestId、requestCommitment、decisionRevision 和 migrationId。字段宽度、作用域、生成者、溢出及重启规则在冻结时逐项确定。设备连接重建不复用旧通信密钥/nonce，旧句柄与迟到响应不进入新身份或新会话。

设备编号不能替代公钥及持有权证明。主机世代是绑定材料，不是主机身份已认证的证据。多 App 会话仍只有一个合法控制连接；App 会话隔离与关闭必须有设备可检查的绑定。

### 5.2 连接、安全和编码

建立流程：版本/能力协商 → 临时密钥及随机数交换 → 绑定握手记录的双端配对码 → 设备实体确认 → 认证加密连接 → 已解锁设备证明持有预期业务 Key → 主机验签并绑定会话。

设备未初始化时，迁移专用连接可以在实体配对后接收导入，不要求它先持有待导入 Key；普通业务仍需身份验证。锁定设备只开放已明确列出的最小信息及配对操作。

冻结时选定成熟密码方案和实现来源，定义完整 transcript、角色/版本绑定、方向密钥、nonce/计数器、AAD、序号、失败恢复和溢出规则。持有权证明由设备构造用途隔离摘要，不直接签主机 challenge。不能新增自创密钥协商作为既有 Channel 的替代。

首版以确定性 CBOR 为候选；最终冻结 map 键序、整数最短编码、金额精度、字节串、UTF-8、未知/重复字段、缺字段、深度及长度规则。包括帧、信封和业务对象的逐字节样本，而不只列概念字段。64 位金额不得经过 JavaScript 不精确 number 或 ESP32 32 位格式化而改变含义。

USB 是字节流，读入边界不是帧边界。定义最大帧/完整消息、分片重组、队列、超时和取消控制优先级，认证覆盖分片关联。若首个冻结版本选择仅单帧，则明确上限并拒绝超限，不声称可传内部大缓冲允许的大交易；该选择必须与首批 Profile 样本一起验证。

### 5.3 请求、状态、结果和撤权

requestCommitment 按 Profile 对实际操作、安全相关证据和显示内容规范编码后计算，由设备重算并比较。必填、非零检查不能替代重算；不能由主机挑选覆盖字段。审核期间冻结内容，变更取消旧请求并重新审核。

结果绑定请求、公钥、会话/世代及承诺；涉及签名的结果按对应业务规则验证，不能随意修改既有业务签名格式以绑定传输元数据。状态区分主机排队、等待用户、执行、完成、拒绝、取消、失效与未知；设备单业务槽，无独立业务 ACK，握手后 REQUEST/RESPONSE/EVENT，取消/查询/心跳等为控制操作。

同一请求重复提交不能二次执行，同 ID 不同承诺必须拒绝。结果查询、缓存淘汰、请求编号及限额一起定义；淘汰结果后仍防止旧请求执行，不能只在缓存命中时防重放。主机结果未知不自动重发；取消只对未执行者保证未执行，已签或已广播不承诺撤回。

会话关闭、失活、锁定、迁移及设备重启清理相关持续决定并使旧队列失效。真正执行前设备复核会话、承诺及授权修订；主机交付前再检查自身权限。事件有运行世代、序号和修订，主机忽略旧事件，事件丢失不能使撤权失效。

错误至少明确 locked、busy、unsupported、version-mismatch、wrong-key、invalid-request、invalid-evidence、denied-once、denied-session、revoked、disconnected、timeout、result-unknown、migration-conflict；数字码与恢复建议在 wire 冻结，不输出秘密。

## 6. 授权范围和审核契约

设备决定为未决定、本次允许、本次拒绝、会话允许、会话否决。持续否决匹配时直接拒绝，不反复弹窗；设备本地可取消任一持续决定，恢复未决定并推进修订。持续决定不跨重启保存。

**单次请求承诺与会话授权范围独立。** 每条消息的承诺覆盖本条内容；Profile 定义能持续允许的共同范围，例如当前 App 会话、对端 A、指定 Channel 协议、方向、操作与限额。设备从实际请求提取并验证范围，不能相信主机自报 grant ID。不能用整条消息摘要或整份 commitment 作为唯一持续匹配条件，让每条消息都重新确认。

Channel 持续授权不能覆盖支付、导出或擦除；没有语义解析器的消息不自动获得宽范围授权。导出和擦除仅一次性专用确认。范围重叠、否决优先级、次数/金额预算、消耗时点、并发和撤销后重新询问在 Profile/Core 一起冻结，不接受无约束的「本会话一切都允许」。

设备 SDK 输出基础审核对象：操作、完整对象标识、金额或权限、范围、签名覆盖和必要风险。字段来自实际操作核验及固定模板；主机信用/业务长说明不进入设备。关键摘要在硬件上明确确认，软件后端在产品已有检查通过后不新增批准。

UserInteraction 返回绑定请求、承诺和修订的决定，不返回无上下文布尔值。换页先松键、确认进度可见、拒绝和锁定可达、返回保留阅读位置、完整对象可查看是行为契约；具体三按钮布局、字号、语言和字体由 Rockey 实现。缺字、控制字符或超限导致关键内容不确定时拒绝，不截掉风险继续授权。

## 7. 业务 Profile

每个 Profile 定义：版本/操作/字段及必填条件、规范编码与承诺、设备验证、审核字段及风险、允许的决定/持续范围/限额、结果/错误、正向及负向向量。未支持的脚本、算法、网络或业务版本明确拒绝。

| Profile | 首版范围与兼容门禁 |
| --- | --- |
| Identity | 原 secp256k1 身份；持有权、身份证明和规范意图对象分别绑定用途/对象/会话；strict DER、compact r\|\|s、low-S 等显式约定，不能隐式二次 hash或直签 challenge |
| BSV P2PKH | 原始交易、前序交易/输出证据、输入索引、金额、脚本、网络、找零、手续费和支持的 sighash；设备核对字节/txid/outpoint/输入归属，自算摘要及所有收款明细；前序字节验证不等于链上已确认/未花费；预览/估费不签名 |
| Channel | 当前 BSV8/Keymaster SDK 的 public/hash/private 编码、签名、nonce 和 seal/open；固定版本及双向向量；保持既有业务 wire，不沿用 Rockey 暂定哈希公钥映射方案 |
| Local Secret v3 | `active-key-hkdf-v1`；HKDF 私钥输入、salt `keymaster.vault.local-secret.v3`、info 为小写压缩公钥文本+NUL+scope；冻结完整 AAD/envelope salt/AES-GCM 规则；内部派生、旧软件密文可解封，不导出长期派生密钥 |
| Content Attestation | 明确主机计算文件摘要及用途，设备构造声明模板；不假称设备读取了文件，不授权付款 |
| Migration | 同 Key 的导入/迁回、进度、持有权和兼容证明；专用设备状态，不开放普通 App 私钥导出 |
| 费用池（待冻结） | 独立核验选定阶段、脚本/双方/资金、sequence/locktime 及状态证据；基础解释和硬件决定，不能套普通 P2PKH 或泛化多签 |
| Evidence（撤销） | 信用/Markdown 属 Keymaster，不作为 VLP 的设备 Profile 或验收依赖 |

新语义域标签不能擅自改变已有 Channel/交易签名；兼容签名按既有规则，新增证明按用途隔离规则。黄金向量记录软件 SDK 的准确来源、版本及输入，避免复制一段摘要后自行猜测格式。

## 8. SDK 需求

### 8.1 TypeScript

拟拆分 `@vaultlink/protocol`（类型、schema/编码、承诺、解析）、`@vaultlink/sdk`（连接、配对、身份验证、会话、请求和事件）及 `@vaultlink/transport-webserial`（串口权限与字节传输）。Profile 模块按版本组织，是否独立包在 V0 固定。

API 以语义 Operation、Session、RequestHandle 和 Result 为中心；connect/pair/verifyIdentity、execute、cancel/query/close 及状态订阅有明确契约。execute 的成功结果表示完成，不把 queued/awaiting-user 当成功。取消能力与结果未知分别表达，不用一个 Promise reject 假称未执行。

Web Serial 权限在有用户交互的 Window 请求；Worker 可通过适配桥使用协议客户端。SDK 接收传输接口，不直接依赖 Keymaster Coordinator。Keymaster 自己实现唯一桥租约和 App 权限，SDK 实现绑定失效及旧结果拒绝。

正常 SDK 不提供 getPrivateKey、signHash、任意 AES/ECDH/HKDF 或远程输入设备 PIN。迁移模块独立入口与能力，不能藏在通用 execute 的任意扩展字段里。原始编解码包不是业务权限接口，设备始终验证语义。

### 8.2 可移植设备 SDK

使用可移植 C++，协议/授权/Profile 与 ESP32/Arduino 分离。适配契约包括 Transport、CryptoProvider、KeyProvider、PersistentStore、UserInteraction、Clock 和 Random。固定内存与资源预算，不能由输入无界分配；密码运算错误显式失败、秘密生命周期清理。

设备 SDK 管理有界解析、认证连接、请求状态、持续决定、撤权、业务验证和结构化审核。KeyProvider 在设备内部执行已授权业务密码操作，不在 wire 或 UI 回调中返回私钥。UI 决定展示方法，不能改写安全语义或代替验证。

Rockey 只实现板级、存储、密码库、Key 保护、时钟/随机及交互适配。参考 SDK 测试必须执行真实编解码、KDF、签名/验签和授权状态机；真实代码运行于公开测试材料，不能以成功替身或 grep 常量伪造结果。

## 9. 迁移与已有仓库接入

软件→硬件阶段为 host-prepared → device-staged → device-committed → host-committed → cleaned。公开记录含迁移 ID、公钥、方向和格式，不含私钥/PIN/密码。设备和主机提交不是跨设备原子事务，每个边界可恢复查询；迁移期间不并行批准两后端业务。

主机提交前保留软件可恢复记录，提交后无自动软件回退。不在设备保留旧软件封装作为默认建议；恢复备份独立格式，最终副本/擦除策略仍待产品确认。硬迁软先验证并提交新的软件封装，再处理设备副本，不能先擦掉唯一可恢复材料。

浏览器注销不自动擦设备；物理擦除由设备专用确认。VLP 标准化迁移共同消息，不实施数据库事务、PIN 界面或备份文件浏览器 UX。

接入关系：VLP 负责共同规格、SDK及向量；Keymaster K1–K7 负责 Vault/数据库/桥/插件接入；Rockey R0–R8 负责硬件适配、UI、密钥保护及真机验收。不得因本项目独立而顺带重写两端无关模块。

## 10. 验收要求
