# 空钱包首页与同身份一次性迁入

2026-10-11：需求已由用户确认，按本文件施工。

空钱包开机进入首页，不要求 PIN，不选择网络。首页可以创建私钥，也可由 Keymaster 导入。浏览器连接仅是右上角状态，替代语言标识，不限制创建；实际创建与实际导入互斥。

创建：用户主动选择创建后设置并重复确认 PIN、选择网络，最终一次性保存身份封装；此前只使用 RAM，PIN 输入时取消或断电不生成钱包。网络选择为必选，不提供取消；左键 Main、右键 Test，按下对应按钮直接选择并保存，中间按钮无操作。

导入：空钱包自动接受最小加密 USB 配对，只在硬件核对校验码。配对后回到首页显示浏览器已连接并等待导入。完整接收原私钥、网络与渠道账本后，由硬件设置并重复确认 PIN，执行一次最终持久化提交。传输暂存阶段的身份、PIN、私钥和配置均在 RAM，禁止按传输步骤写 Flash。

一次提交是逻辑事务：必要的文件写入在最终确认后集中执行，成功回执必须在封装、渠道账本及迁移提交记录持久化并核验后签发。断电或写入失败不得发送成功回执；浏览器保留软件私钥，以同迁移 ID 恢复最终提交。

Keymaster 必须验证原公钥签署的保存成功证明后，在本地原子事务中将原 Key 后端换为硬件并移除软件私钥封装。公钥、网络身份、业务数据、渠道配置与账本保留，不需要再次添加/导入硬件钱包。回执丢失可重连核实同一次迁移，不能将传输临时身份作为钱包身份。

## 施工及验证结果

RocKey 空钱包开机进入首页，右上角以加密会话状态显示浏览器连接；创建入口在未开始实际迁入时可用。创建中的 PIN 与网络只保存在 RAM，PIN 输入阶段可取消回首页；网络页必须选择网络并按中间确认后保存。空首页自动准备受限 USB 临时配对；收到完整私钥后显示本机 PIN 设置与重复确认，数字变化局部重画，最终输入完成先显示“正在保存钱包…”再执行 KDF 与集中持久化。传输中的 journal、元数据和 bank 不写 Flash，真正保存阶段才写入恢复记录、账本、封装及提交阶段。

Keymaster 临时迁入连接接受尚未绑定网络的 `identity.network={bsvNetwork:null}`，在 import-begin 传原钱包网络；普通硬件连接继续核验实际网络与公钥。保存成功证明经原公钥挑战验签，且阶段必须是 device-committed 或后续阶段，之后 IndexedDB CAS 原子替换为硬件公开记录、迁移记录与原账本。当前 Key 后端变为硬件，业务数据保留；无再次添加硬件钱包步骤。临时连接不能充当普通签名身份，后续普通连接仍核验实际导入公钥。
