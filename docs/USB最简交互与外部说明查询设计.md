## 1. USB 逻辑消融后的基线

- 保留 USB 认证加密、实体配对、Key 持有权证明、请求绑定、防重放、取消、撤权和失活锁定。信用服务通信不进入此设备链路。
- 每个协议版本使用一个固定安全套件，不增加多算法协商；操作能力及版本声明保留。已有 VLP Draft 的套件是对齐起点，不把单独选择原语等同于完整握手已验证。
- 握手后的消息收敛为 `REQUEST`、`RESPONSE`、`EVENT`。握手保留所选套件所需消息，不机械塞进业务三类型。
- 查询、取消、心跳、锁定、会话关闭以控制操作表达，不再单独扩张消息类型。取消明确指定目标请求；控制请求与业务请求的编号/关联规则在联合冻结时定义。
- 移除独立业务 ACK/ACK_REQUIRED；收到字节不代表授权或执行成功。可用 EVENT 表示等待用户等进度，RESPONSE 给最终结果。主机超时只表示结果未知。
- 设备同一时刻只有一个活动业务请求；主机维护有界业务队列，设备忙时拒绝新的独立业务请求。控制请求不排在业务队列后，不占第二个业务槽。
- 多 App 会话仍隔离；一时刻一个业务请求不等于只有一个 App 会话。本次允许/拒绝仅属于当前请求；只有会话允许/否决写入设备会话决定表，可由设备取消。
- 当前请求承诺与持续授权范围分别保留：前者绑定这一次不可变操作，后者表达可重复使用的语义范围。
- 最小结果缓存仅保存当前/最近完成的业务请求及其结果；结合连接内单调递增、不得回绕的业务 requestId 接受水位，拒绝旧编号重新执行。重复编号且内容不同也拒绝；正在执行的重复请求只返回状态，不重新执行。
- 查询当前/最近结果；已淘汰结果返回不可确定/不可查询，不伪称未执行。缓存淘汰不能解除防重放；不能用“缓存满后永久拒绝新业务”代替水位设计。编号宽度、编码与持久迁移查询另行冻结。
- 断线、超时、重启后不自动重放签名、付款、迁移等结果未知请求；迁移仍使用独立持久 journal，不用最近结果缓存替代。
- Keymaster 内部钱包/后端/Coordinator 世代继续保留。wire 合并为 hostContextId 只是有条件的简化：须证明任一上下文变化必定结束旧连接、撤销旧授权并清理任务；不能证明时继续传明确世代字段。
- 保留有界帧与长度检查。是否分片依据实际交易容量冻结；当前单帧实现不能作为删除分片能力的理由。采用分片时固定总长、片数、超时及重组内存上限，不引入无界流。

本节是目标设计，现有固件消息类型、队列和缓存并不自动符合；需两端按同一版本施工。不得静默兼容旧消息或降级到明文。
