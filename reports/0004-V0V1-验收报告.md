而不是 grep 源码常量；关键负向样本确定失败。对应 VLP-01、02。」

| 门禁要素 | 状态 | 证据 |
| --- | --- | --- |
| 两个独立执行路径产生相同规范字节 | **达成** | 路径 A `tools/refgen/vlp_ref.py`（Python 标准库）生成期望；路径 B `conformance/run.js`（Node 自实现编解码）独立复核。覆盖 CBOR、帧、transcript、HKDF、配对码、持有权摘要、承诺、Local Secret 派生、P2PKH sighash |
| 密码向量实际执行实现而非 grep 常量 | **达成** | HKDF（A.1/A.3）、HMAC（RFC 4231 #2）、SHA-256/256d、RIPEMD-160、AES-256-GCM（NIST TC16 + 篡改拒绝）、X25519（RFC 7748 §6.1）、ECDSA 验签路径均由成熟实现**实际执行**。`0002` §6 G5 指出的 grep 源码做法未被沿用 |
| 关键负向样本确定失败 | **达成** | 结构层 20 项（路径 A 与 B 各自拒绝）+ 业务层 14 项（schema 校验）+ 语义层 24 项（帧 5 / 承诺 4 / 密码 4 / 交易 10 / 握手 2 声明），合计 58 项 |

### 4.1 密码覆盖的诚实边界

| 原语 | 覆盖方式 | 未覆盖 |
| --- | --- | --- |
| SHA-256 / SHA256d / HMAC / HKDF / RIPEMD-160 | 两条独立路径 + 公开标准向量 | — |
| AES-256-GCM | Node 成熟实现 + NIST 向量 + 篡改拒绝 | 设备侧 GFASH 自实现的多长度差分（属 V4/V5） |
| X25519 | Node 成熟实现 + RFC 7748 向量 | RFC 7748 §6.1 低阶点拒绝、1000 次迭代向量（属 V4/V5） |
| ECDSA secp256k1 | **仅验签路径**（真实签名 + 错误公钥拒绝） | **签名路径未验证**：Node 用随机 nonce，与 RFC 6979 确定性不对齐；见 §6 |
| Base58Check / P2PKH 地址 | 两条路径 + 公开测试公钥地址 | — |

## 5. 审计发现与处置

`decisions/0002-差异清单.md` 记录 7 项阻断、15 项须冻结、8 项文档矛盾、5 项外部待定、6 项覆盖缺口。

本轮**已在规范中给出正确规则并由参照实现落实**的阻断项：

| 编号 | 阻断 | 本轮证据 |
| --- | --- | --- |
| B1 | Reader 容器状态非栈，嵌套 map 解析失败 | 两条路径均实现层级栈；`cbor:nested-containers` 逐字节一致且可往返 |
| B2 | `MatchKey.commitment` 从不参与匹配 | 规范拆分 `requestCommitment`（逐请求）与 `grantScope`（范围）；`scope:commitment-is-per-request`、`commitment:variants-differ` |
| B3 | 三个世代字段恒为 0 | 规范改为世代变化时清空全部持续决定（`spec/core/05` §4.3） |
| B4 | c2s nonce 在解密失败时照常推进 | 规范要求成功才推进、失败即断链（`spec/security/01` §5）；本轮未实现链路状态机（属 V2） |
| B5 | `secret.seal` 长明文溢栈 | 明文上限收敛到 512、编码器对缓冲不足返回错误（`spec/profiles/04` §3.1）；`schema:neg:*` 覆盖字段上限 |
| B6 | `check_wire_encoding.py` map 计数检查是死代码 | 两条路径的 Writer 均自校验声明对数（`cbor:pair-count-self-check`） |
| B7 | Writer 无法输出嵌套 map | 同 B1 |

**尚未在本仓库修复**：这些缺陷存在于 Rockey 固件与脚本中，修复属 V7 跨仓库任务，
需另行授权。规范已按正确语义冻结，Rockey 需升级后才声明兼容。

## 9. 已知限制

1. `spec/profiles/03-channel.md` 只冻结了 VLP 侧的封装，**BSV8 SDK 的字段 schema
   未逐项抄录**（JCS 规则、scope 字符串、ECDH、信封格式以
   `bsv8-channel-protocol@0.6.0` 为准）。V5 必须补齐逐字节 schema 与向量。
2. `spec/profiles/07-migration.md` 的 `migration.status` 结果格式已冻结，
   但 `export` 的密文格式未冻结（属产品验收）。
3. 单帧上限使 VLP 0.1 **无法承载**现有实现声明的 `rawTx ≤ 8192`。
   大交易需 VLP 0.2 的分片规格；本轮不声称支持。
4. `grantScope` 的规范编码在 `test-vectors/policy/scope.json` 给出样本，
   但完整的 Profile→scope 提取规则仍需在 V4 的设备 SDK 中实现并补向量。
