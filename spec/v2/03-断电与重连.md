# 无电池/有电池设备：断开与重连

日期：2026-10-09。以无电池硬件为默认，不依赖拔掉后还能处理清理消息。身份 Key、持久配置与 USB/App 会话必须分开。

| 状态 | 无电池设备 | 有电池设备的最小模式 |
| --- | --- | --- |
| USB 拔出 | 立即断电，不能保证执行任何 close 指令 | 固件发现断开后锁 Key、失效 USB 密码会话和易失 scope 决定；保留 App 累计账本 |
| 再次接入 | 启动锁定，三按钮/PIN 本地解锁 | 使用同一重连流程；本版不保留免解锁续用分支 |
| 链路 | 新临时密钥、nonce、连接 ID，完整配对及持有权证明 | 相同 |
| 当前身份 | 验证同一预期公钥，继续现有 Keymaster 身份/数据 | 相同 |
| 渠道配置 | 从本 Key 持久状态恢复，不自动清空/提高 | 相同 |
| 旧 App 会话 | 按持久 active/closed 标记恢复，used 不重置；已关闭会话不可复活 | 相同 |
| 待处理付款 | 旧 reserved 转 unknown，占用保留；signed/unknown 保留 | 相同 |

Keymaster 状态流程：`disconnected → connected_locked → unlocking → pairing → identity_verified → ready`。USB 授权/端口重开只是传输准备，不代表解锁成功，也不代表绑定到同一私钥。不同公钥拒绝当前钱包接入，不能自动换根 Key 或抹除原数据库。注销/删除后导入另一 Key 的产品流程仍由 Keymaster 实施。

断开时主机终止旧 client，把未完成业务显示为结果未知，不自动重发、不自动“退款”。设备没有电池时无须先给主机发告别消息。重连的 USB 请求 ID 可从新连接重新开始，但 paymentId 是持久业务标识，不能更换 connectionId 就再次执行同一付款；改变 paymentId 也不能让 Keymaster把未知付款当作成功取消并自动再付。

App 会话和 USB 会话不是一一对应：一条 USB 链路可服务多个 App。断链结束 USB 执行授权和本地秘密持续决定，但不等于 App 主动结束连接。设备重启保留 App 会话 active/closed 状态、used 与历史证据；主机必须重新 PIN/配对/持有权核验，再恢复同一 App 连接预算。App 真正断开通过 payment.session-close 关闭指定会话，不能用同一 ID 复活。新 App 会话从默认额度开始的前提是用户重新确认；不允许后台靠反复拔插/重连领取新额度。

## 实现与适配边界

- SDK 已实施：断链销毁记录密钥/client、旧 DeviceIdentityKey 可关闭清零、PaymentPolicy 载入保留会话和占用、旧预占转 unknown、保留渠道/金额/付款防重放记录；独立执行器退出后不得复用。
- 设备适配必须实施：上电始终锁定、硬件本地 PIN 解锁后才装载 Key、每启动新的 deviceRunId、每连接新的 connectionId、断连立即锁定、持久存储原子性与防回滚。DeviceServer 的 onLock 回调必须关闭 Key 和旧 Policy；不得从 USB 接收 PIN。
- 主机适配必须实施：以 current wallet 的期望公钥校验，USB 断开锁钱包，App 真正断开关闭指定会话；重新验证钱包后恢复同一 App 预算而不是新建零已花会话；允许用户看到旧未知结果，但不能把主机记录当设备未执行证明。
- SDK 软件重载测试验证这些状态规则，不等于已经验证真实设备 Flash/PIN/拔插时序。DeviceServer 依赖传输适配报告 EOF/异常；真实掉线检测和供电类型由固件负责。

真机验收至少覆盖：预占持久提交前/后、签名后/交付前拔插；旧与新公钥重连；无电池即时掉电；带电池断连自动锁定；配置写入途中断电；反复重连不能静默重新授予预算。未完成这些检查前不能宣布真机断电恢复通过。

## 首次绑定与既有身份重连

SDK `enrollHost` 仅供无现有钱包身份的首次绑定。它接受 ACK 中的候选公钥作为本次握手对象，经两端明确配对与新鲜挑战签名验证后才返回 `{client,publicKey}`；不引入额外 USB 消息。它证明用户本次配对设备持有该 Key，不证明厂商来源或物理防篡改。已有钱包必须调用 `connectHost(...expectedPublicKey...)`，不同 Key 拒绝，不得捕获 wrong-key 后改调用 enrollHost。

首次公开记录由 Keymaster 条件初始化事务提交；只有 Key 缺席才允许创建，事务失败不得构造第二身份。VLP 连接成功不替代本地身份/世代/Root 检查。迁移需要专用流程和账本转移，不能用首次绑定替代。


## 私钥迁移的恢复例外

普通硬件激活仍要求当前 Key 的持有权。迁移未完成只接入同一 journal 的专用恢复连接，不把 USB 连接成功当成业务解锁。设备旧 Key 已删除时使用 Draft 0x231 的临时身份/实体配对回执连接，只核对浏览器已原子提交的同一目标；它不是旧 Key 的持有权证明。具体字段、阶段及实体清理见 [付款账本迁移](08-付款账本迁移.md)。真实 Flash 断电及实体 USB/PIN 仍需验收，主机阶段夹具不替代这些验收。

软件迁入的断点：NoKey + staged 重新在设备本机设置 PIN，只恢复同一公开 journal 和 bank 前缀；已有实际封装 + staged 用原 PIN 解锁并挑战证明后补写 device-committed；浏览器 local-committed 只证明实际同 Key 并确认同 targetHash，禁止重传源私钥或生成另一身份。临时导入连接不授予普通业务能力。
