# 07 错误码

> VLP 0.1 Draft · 决策见 [D-010](../../decisions/0003-冻结决策.md)。
> 需求 §5.3 列出的 14 类错误在此冻结为 wire 数字码。

## 1. 编码

`error` 为 `u32`，取值 0–14。错误响应使用 `RESPONSE` 帧，
`payload` 为 map(2)，键序：

| 序 | 键 | 键长 | 类型 |
| --- | --- | --- | --- |
| 1 | `error` | 5 | u32 |
| 2 | `requestId` | 9 | u32 |

## 2. 错误码表

| 码 | 名称 | 含义 | 可重试 | 恢复建议 |
| --- | --- | --- | --- | --- |
| 0 | `ok` | 成功 | — | — |
| 1 | `locked` | 设备锁定 | 是 | 解锁后重试；**不得**自动重发 |
| 2 | `busy` | 队列满、结果缓存满或已有同 ID 请求在处理中 | 是 | 稍后重试或查询 |
| 3 | `unsupported` | 操作/字段/Profile 版本未声明支持 | 否 | 升级或改用已声明能力 |
| 4 | `version-mismatch` | `protocolVersion` 或 Profile 版本不符 | 否 | 固定到兼容版本；**不降级** |
| 5 | `wrong-key` | 持有权证明失败或公钥非预期 | 否 | 检查是否换过 Key；**不得**重试 |
| 6 | `invalid-request` | 结构、必填、上限、承诺不匹配、重复键、乱序 | 否 | 修正请求；**不得**重试 |
| 7 | `invalid-evidence` | 证据验签或信任根校验失败 | 否 | 重新取得证据 |
| 8 | `denied-once` | 本次被用户拒绝 | 否 | 需重新确认 |
| 9 | `denied-session` | 命中持续否决 | 否 | 需用户在设备上取消该决定 |
| 10 | `revoked` | 授权已撤销 | 否 | 需重新确认 |
| 11 | `disconnected` | 连接断开 | 是 | 重新握手后按 §2 决定是否重发 |
| 12 | `timeout` | 超过 TTL 或握手/存活超时 | 是 | 查询结果后决定；**不得**盲重发 |
| 13 | `result-unknown` | 设备无法确定是否已执行 | **否** | 只能查询；**禁止自动重发** |
| 14 | `migration-conflict` | 与进行中的其它迁移冲突 | 否 | 等待当前迁移结束 |

## 3. 重试规则

| 类别 | 码 | 规则 |
| --- | --- | --- |
| 可安全重试 | `busy`、`timeout`、`disconnected` | 主机**必须先查询**原 `requestId`；查询无终态才可重试，且重试必须带**相同** `requestCommitment` |
| 需用户介入 | `locked`、`denied-once`、`denied-session`、`revoked` | 重试无效，需状态或用户动作改变 |
| 禁止重试 | `wrong-key`、`invalid-request`、`version-mismatch`、`unsupported`、`migration-conflict` | 重试无意义 |
| **禁止自动重发** | `result-unknown` | 任何情况下不得自动重发；只允许查询 |

**ACK 不等于成功。** 收到 `RESPONSE` 且 `error=0` 才表示请求到达终态。

## 4. 与 Keymaster 错误体系的关系

VLP 的数字码是**新定义**。Keymaster 侧现有三套互不相干的错误体系
（`ChannelSubscriptionErrorCode`、`StorageErrorCode`、`ProtocolErrorCode`）
各自映射到 VLP 码，**不修改** Keymaster 的既有枚举。

映射表由 V7 接入任务提供；映射表缺失时按最保守方式处理：
任何未知码一律视为"结果未知"，不推断成功。

## 5. 无秘密输出

错误负载**不得**包含私钥、PIN、密码、口令或任何可用于推导它们的材料。
错误 `text` 只允许：

- Profile 的稳定错误标识；
- 设备生成的固定文案；
- 主机提供的**非安全相关**上下文（如 `requestId`、操作名）。

## 6. 与请求状态的对应

| 错误码 | 终态 |
| --- | --- |
| `ok` | `completed` |
| `denied-once` / `denied-session` / `revoked` | `denied` |
| `cancelled`（取消通道） | `cancelled` |
| `timeout` | `expired` |
| `result-unknown` | **不产生设备侧终态**；主机侧为 `unknown` |
| 其余 | 按 [06](./06-请求状态与事件.md) §1 迁移到对应终态 |

`result-unknown` 是**唯一不产生设备侧终态**的码：设备无法判定是否已执行，
因此不得谎称 `cancelled` 或 `completed`。
