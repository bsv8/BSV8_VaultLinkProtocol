# 03 帧与消息层

> VLP 0.1 Draft · `protocolVersion = 1` · 决策见
> [D-003](../../decisions/0003-冻结决策.md)、[D-004](../../decisions/0003-冻结决策.md)、
> [D-016](../../decisions/0003-冻结决策.md)。

## 1. USB 是字节流

读入边界**不是**帧边界。禁止把一次 read 当成一帧。
帧解析器必须处理断包、粘包、噪声前缀与半帧。

## 2. 帧格式

固定 11 字节头 + 负载 + 4 字节尾：

```
偏移  长度  字段
 0     1    magic0 = 0xA5
 1     1    magic1 = 0x5A
 2     1    version = 1
 3     1    type
 4     1    flags
 5     4    seq            小端 u32
 9     2    payloadLen     小端 u16，且 ≤ MAX_FRAME_PAYLOAD
11     L    payload
11+L   4    crc32          小端 u32，覆盖 [2, 11+L)
```

`crc32` 为 **CRC-32/ISO-HDLC**（反射多项式 `0xEDB88320`，init `0xFFFFFFFF`，
末尾异或 `0xFFFFFFFF`）。校验值 `CRC32("123456789") = 0xCBF43926`。
**magic 两字节不计入 CRC**。

### 2.1 帧类型

| type | 名称 | 加密 | 方向 |
| --- | --- | --- | --- |
| `0x01` | `HELLO` | 否 | 主机 → 设备 |
| `0x02` | `HELLO_ACK` | 否 | 设备 → 主机 |
| `0x03` | `PAIR_CONFIRM` | 是 | 主机 → 设备 |
| `0x04` | `PAIR_OK` | 是 | 设备 → 主机 |
| `0x05` | `POSSESSION_PROVE` | 是 | 主机 → 设备 |
| `0x06` | `POSSESSION_OK` | 是 | 设备 → 主机 |
| `0x10` | `REQUEST` | 是 | 主机 → 设备 |
| `0x11` | `RESPONSE` | 是 | 设备 → 主机 |
| `0x12` | `EVENT` | 是 | 设备 → 主机 |
| `0x13` | `QUERY` | 是 | 主机 → 设备 |
| `0x14` | `QUERY_RESULT` | 是 | 设备 → 主机 |
| `0x20` | `PING` | 是 | 双向 |
| `0x21` | `PONG` | 是 | 双向 |
| `0x30` | `ABORT` | 是 | 双向 |

### 2.2 帧标志

| 位 | 名称 | 含义 |
| --- | --- | --- |
| `0x01` | `ACK_REQUIRED` | 需要传输层确认（**不等于**授权或执行成功） |
| `0x02` | `CANCEL` | 走取消通道；**只对尚未执行者保证未执行** |
| 其它 | — | **必须为 0**，非零即拒绝 |

`CANCEL` 与控制消息有独立优先级，但**不能跳过认证**。

### 2.3 非法输入处置

| 情形 | 处置 |
| --- | --- |
| magic 不匹配 | 丢弃至下一个可能的 magic 起点，计入 `resync` |
| `version != 1` | 丢弃帧，计入 `dropped` 与 `resync` |
| `payloadLen > MAX_FRAME_PAYLOAD` | **仅凭头即拒绝**，丢弃，计入 `dropped` |
| CRC 不符 | 丢弃，计入 `dropped` |
| 负载长度与声明不符 | 丢弃，等待更多输入 |
| 缓冲溢出 | 丢弃整个缓冲，当前字节重新作为新候选帧首字节 |

**主机自报的无界长度不得被分配。** 不支持外部压缩。

## 3. 限额与容量验证

| 限额 | 值 |
| --- | --- |
| `MAX_FRAME_PAYLOAD` | **1024** 字节 |
| `MAX_MESSAGE`（明文业务消息） | **896** 字节 |
| 帧头+尾开销 | 15 字节 |
| AEAD 开销（tag） | 16 字节 |

因此单帧可承载的**明文**上限为 `1024 − 16 = 1008` 字节，业务消息再留
安全余量取 **896**。

> 这不是照抄现有实现的 1536/1400。VLP 0.1 选择**仅单帧**（[D-016](../../decisions/0003-冻结决策.md)），
> 上限由首批 Profile 样本实测反推得到，实测数据见 §5。

### 3.1 接收缓冲必须容纳声明上限

接收缓冲 = `MAX_FRAME_PAYLOAD + 11 + 4 = 1039` 字节。
**溢出判定必须在字节累加时进行**，且判定式必须允许恰好装下一帧声明上限的负载。

> 现有实现的守卫式 `len + 15 > sizeof(buf)` 使实际可收 1522 而非声明的 1536
> （[0002](../../decisions/0002-差异清单.md) §2 S2）。VLP 要求声明上限 == 实际上限。

## 4. 记录加密

| 项 | 规则 |
| --- | --- |
| 算法 | AES-256-GCM |
| 密钥 | `c2sKey` / `s2cKey`，方向分离，**不得共用** |
| nonce | 12 字节，见 §4.2 |
| tag | 16 字节，附于密文尾部 |
| AAD | 见 §4.1，**总是认证** |

### 4.1 AAD

```
aad[0]    = type
aad[1]    = flags
aad[2..5] = seq             大端 u32
aad[6..9] = deviceRunId     大端 u32
```

共 10 字节。整数一律**大端**（[D-004](../../decisions/0003-冻结决策.md)）。
`HELLO`/`HELLO_ACK` 不加密，无 AAD。

### 4.2 nonce

```
nonce = baseNonce[dir] + counter[dir]      (mod 2^96，按 96 位大端相加)
```

`counter` 为 64 位，占据 96 位块的低 8 字节；高 4 字节为 0。
进位在 96 位内传播，最高位进位丢弃。

**计数器只在认证成功时推进**；任何认证失败必须**中止当前连接**。
不得在失败后继续使用错位的 nonce 链。

> 修复已知实现中"解密失败仍推进计数器导致链路永久错位"的缺陷
> （[0002](../../decisions/0002-差异清单.md) §1 B4）。

**溢出**：任一方向的 `counter` 达到 `2^64 − 1` 时，设备必须重建连接
（新 `deviceRunId`、新临时密钥），**不回绕**。

## 5. 首批 Profile 样本容量实测

施工单 V0 第 9 项要求用真实样本验证容量，**不把 1400/1536 等实现数值当成充分证据**。
下表数值由 `tools/refgen` 从真实样本测得，权威副本在
`test-vectors/limits/frame-capacity.json`，由 `conformance/` 复核。

| 样本 | 编码后明文字节 | ≤ 896 |
| --- | ---: | --- |
| `cap-p2pkh-1in-2out` 典型 1 输入 2 输出 | 289 | 是 |
| `cap-p2pkh-4in-6out` P2PKH 上限样本 | 855 | 是 |
| `cap-local-secret-512` 明文 512 字节 | 661 | 是 |
| `cap-channel-512-old` 消息 512 字节 | 629 | 是 |
| `cap-local-secret-4096-old` 明文 4096 字节 | 4245 | **否 → 超限拒绝** |

**结论**：P2PKH 上限（4 输入 6 输出）、Channel 512 字节消息与
Local Secret 512 字节明文在收敛后的上限内**可**单帧承载；
现有实现声明的 `plaintext ≤ 4096` **不可**。

因此各 Profile 的字段上限按本表收敛，超限**明确拒绝**并返回
`invalid-request`——**不声称**可传大交易或长文。

现有实现声明的 `rawTx ≤ 8192` 与 `channel message ≤ 512` 的组合
在旧帧限额（1536/1400）下亦不成立：`rawTx ≤ 8192` 从未被旧限额真正承载过。
`msg ≤ 512` 收敛为 ≤ 512 且已验证可容纳。

## 6. 消息信封

### 6.1 REQUEST

`VLP-CBOR-1` map，键序（长度，再字节序）：

| 序 | 键 | 键长 | 类型 | 必填 |
| --- | --- | --- | --- | --- |
| 1 | `op` | 2 | text | 是（**必须是第一个键**） |
| 2 | `opVersion` | 9 | u32 | 是 |
| 3 | `body` | 4 | bytes | 是 |

`op` 键长为 2，是最短可能键长，因此确定性键序保证它排第一。
解析器发现 `op` 之前出现其它键即拒绝。

### 6.2 请求元数据

`body` 之外由链路层强制注入并校验（不可由请求体携带）：

| 项 | 规则 |
| --- | --- |
| `requestId` | 连接/会话内唯一；同 ID 不同承诺 → 拒绝 |
| `requestCommitment` | 32 字节，必填，非全零（[D-005](../../decisions/0003-冻结决策.md)） |
| `sessionId` / `sessionEpoch` | 必须与已开启会话**完全一致** |
| 三个主机世代 | 必须与建立会话时**完全相同** |
| `deviceRunId` / `connectionId` | 必须与当前连接一致 |

主机不得中途改写世代来复用已开启的授权窗口。

### 6.3 RESPONSE

map(2)，键序：

| 序 | 键 | 键长 | 类型 |
| --- | --- | --- | --- |
| 1 | `payload` | 7 | bytes 或 `null` |
| 2 | `requestId` | 9 | u32 |

错误响应同样用 `RESPONSE` 帧，`payload` 为
`{ "error": u32, "requestId": u32 }`（键序 `error(5) < requestId(9)`）。

**结果绑定**：结果必须可关联到 `requestId`、业务公钥、会话/世代与承诺。
涉及签名的结果按对应 Profile 的业务规则验证，**不得**为绑定传输元数据
而修改既有业务签名格式。

## 7. 事件

`EVENT` 帧，map(3)，键序：

| 序 | 键 | 键长 | 类型 |
| --- | --- | --- | --- |
| 1 | `payload` | 7 | bytes 或 `null` |
| 2 | `eventSeq` | 8 | u32 |
| 3 | `deviceRunId` | 12 | u32 |

`payload` 为事件体，map 键序 `kind(4) < …`（见 [06-请求状态与事件](./06-请求状态与事件.md) §4）。

**规则**：

- `eventSeq` 在运行世代内单调递增，从 1 开始。
- 主机**忽略** `eventSeq` 小于已见最大值的旧事件。
- **事件丢失不使撤权失效**：撤权在设备侧即时生效，主机交付结果前自行复查。
- 事件结构完整冻结（现有实现的 `EVENT` 负载未定义，
  [0002](../../decisions/0002-差异清单.md) §3）。

## 8. 分片

**VLP 0.1 不支持分片。** 单帧承载，超限拒绝
（[D-016](../../decisions/0003-冻结决策.md)）。

分片（含分片 ID/序号、重组队列、认证覆盖分片关联）作为传输独立规格的后续范围，
不默认为已支持。

## 9. 超时

| 项 | 值 | 说明 |
| --- | --- | --- |
| 链路存活探测间隔 | 1000 ms | 设备发加密 `PING` |
| 链路失活超时 | 8000 ms | 主机侧无有效帧即失活 |
| 握手超时 | 60000 ms | 超时后设备回到待握手，**不锁定** |
| 请求 TTL | 120000 ms | 超时按 `timeout` 结束并失效 |

失活超时**必须**导致清空持续决定、清队列并锁定；不能凭 USB 供电持续就保留授权。
