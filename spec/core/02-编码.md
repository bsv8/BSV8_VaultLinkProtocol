# 02 规范编码 VLP-CBOR-1

> VLP 0.1 Draft。决策见 [D-001](../../decisions/0003-冻结决策.md)、[D-002](../../decisions/0003-冻结决策.md)、
> [D-008](../../decisions/0003-冻结决策.md)。
>
> **本规范是 wire 接口的一部分。** 改这里的规则等于改线缆版本。
> 第三方必须能仅凭本文件构造出与参考实现逐字节相同的输出。

## 1. 为什么编码规则是接口

同一语义只有唯一字节序列，否则：签名与摘要不可复现、防重放与承诺比对失效、
两端静默分叉。所以键序、整数表示、长度与上限全部规范化，不接受"等价编码"。

VLP 选定确定性 CBOR 子集，标识为 **`VLP-CBOR-1`**。

> **`VLP-CBOR-1` 不是 RFC 8949 的核心确定性编码。**
> 差异见 §2。声称 RFC 8949 §4.2 合规的编码器**会被 VLP 拒绝**。

## 2. 与 RFC 8949 的差异

| 项 | RFC 8949 核心确定性 | `VLP-CBOR-1` |
| --- | --- | --- |
| map 键序 | §4.2.1 纯字节序（bytewise lexicographic） | **长度优先，再字节序**（§3.3） |
| 文本串 UTF-8 | 要求良构 | **要求良构并校验**（§2.4） |
| 嵌套容器 | 支持 | **支持，深度上限 6**（§3.5） |
| 整数表示 | 最短 | 最短（§2.3） |
| 标签 major 6 | 支持 | **禁止**（§2.2） |
| 不定长 | 支持 | **禁止**（§2.2） |
| 浮点 | 支持 | **禁止**（§2.2） |

## 2.1 允许的类型

| major | 类型 | 允许 |
| --- | --- | --- |
| 0 | 无符号整数 | 是 |
| 1 | 负整数（`−1 − n`） | 是 |
| 2 | 字节串 | 是 |
| 3 | 文本串（UTF-8） | 是 |
| 4 | 数组 | 是 |
| 5 | map | 是 |
| 6 | 标签 | **否** |
| 7 | 简单值/浮点 | 仅 `false`(0xF4)、`true`(0xF5)、`null`(0xF6)；其余 simple 与全部浮点 **否** |

## 2.2 禁止的形式

以下编码一律拒绝（**不是**"能解析就算"）：

- 不定长（additional info 31）：字符串、数组、map。
- 标签（major 6）。
- 浮点（major 7 且 ai 25/26/27）、`undefined`(0xF7)、simple value（ai 24）。
- 非最短整数：`0x18 0x17`（23 写成两字节）、`0x19 0x00 0xFF`（255 写成三字节）等。
  **长度参数同样必须最短**——`0x58 0x05` 后跟 5 字节合法，
  `0x58 0x05` 表示长度 5 是最短；但 `0x59 0x00 0x05` 是非最短，拒绝。
- 尾随字节：解析结束后缓冲区必须恰好耗尽。

## 2.3 整数

一律最短表示：

| 值域 | head 字节数 |
| --- | --- |
| 0…23 | 1 |
| 24…0xFF | 2（`0x18`） |
| 0x100…0xFFFF | 3（`0x19`） |
| 0x10000…0xFFFFFFFF | 5（`0x1A`） |
| ≥ 0x100000000 | 9（`0x1B`） |

参数一律**大端**。负整数 major 1 的参数为 `−1 − v`（无符号）。

**有界要求**：任何 u64 字段在 Profile 未显式放宽时，上限为 `2^32 − 1`；
溢出拒绝，**不允许回绕**。

## 2.4 字节串与文本串

| 项 | 规则 |
| --- | --- |
| 字节串长度 | 由调用方上界约束，解析时校验 `声明长度 ≤ 输入剩余字节`，**不预分配** |
| 文本串 | 必须是**良构 UTF-8**：无过长编码、无代理区码点（U+D800–U+DFFF）、无 > U+10FFFF、无 NUL 之外的禁止字符由 Profile 规定 |
| 空文本 | 允许；但 Profile 字段通常要求非空（见各 Profile） |
| 空字节串 | 编码为 `0x40`，与"无值"**不同**：无值使用 `null`(0xF6) 或字段省略 |

## 3. 结构规则

### 3.1 map

- 键必须是文本串，长度 ≤ 31 字节。
- map 的键数必须与编码器声明的一致，且解析结束后必须全部消费。

### 3.2 必填与未知字段

| 规则 | 内容 |
| --- | --- |
| 必填缺失 | 该消息无效；按消息类型返回对应错误码（通常 `invalid-request`） |
| **未知字段** | **一律拒绝**。不允许夹带降级字段或未来字段 |
| 重复字段 | **一律拒绝**（由 §3.3 的键序唯一性保证） |
| 可选字段 | 省略与显式 `null` **不等价**：`null` 是非法值 |

### 3.3 键序（唯一性规则）

map 的键必须按 **(字节长度, 字节序) 严格递增**：

```
键 A 合法地排在键 B 之前 ⟺  len(A) < len(B)  或  ( len(A) == len(B)  且  A <lex B )
```

- 长度相等且字节序相等 → **重复键，拒绝**。
- 长度相等且字节序更大 → **乱序，拒绝**。
- 长度更小 → **乱序，拒绝**。

编码器与解码器都必须强制校验。解码器一旦发现违规立即失败，**不得继续解析**。

> 键序表因此可以直接按长度排序写出来并肉眼核对。
> 例：`body(4) < op(2)` 不合法；正确是 `op(2) < body(4)`。

### 3.4 容器状态必须按层级

编码器与解码器的容器状态（`inMap`、`itemsLeft`、`lastKey`）**必须按层级栈保存**，
不得用单层字段。

嵌套 map/array 是**合法且必须支持**的形状——`bsv.p2pkh-sign` 的 `prevouts`
是数组套 map，`local-secret` 的 `sealed` 是 map 套 map。

> 这是对已知实现缺陷的修复，见 [0002-差异清单](../../decisions/0002-差异清单.md) §1 B1/B7。

### 3.5 深度与长度上限

| 限制 | 值 | 说明 |
| --- | --- | --- |
| 嵌套深度 | ≤ 6 | 顶层容器计为 1 |
| 键名长度 | ≤ 31 字节 | |
| map 对数 | ≤ 24 | 顶层消息；元素内更小 |
| 数组元素数 | 由 Profile 冻结 | 且 `声明元素数 ≤ 输入剩余字节` |
| 字节串长度 | 由 Profile/消息类型冻结 | |
| 总缓冲 | 由帧上限决定（[03-帧与消息](./03-帧与消息.md)） |

深度超限、声明长度超过剩余输入、容器未消费完 —— 一律拒绝，**不得部分接受**。

### 3.6 必须自校验

编码器**必须**校验自己声明的 map 对数、数组元素数与深度；缓冲不足时
**返回错误**，禁止静默截断或输出未初始化内存。

> 这是对已知实现缺陷的修复，见 [0002](../../decisions/0002-差异清单.md) §1 B5/B6。

## 4. 金额与整数表示

| 项 | 规则 |
| --- | --- |
| 金额单位 | satoshi，u64 |
| 编码 | CBOR major 0，最短表示（§2.3） |
| JS 表示 | 必须用 `BigInt`。**禁止**经 JavaScript `number` |
| 嵌入式表示 | 必须用 64 位格式化。**禁止**经 32 位格式化 |
| 显示与签署 | 显示值与签署值必须来自同一 u64，不得二次舍入 |
| 溢出 | 见 §2.3；累加溢出视为超限（D-007） |

## 5. 十六进制与大端

| 项 | 规则 |
| --- | --- |
| hex 字符串 | wire 上的 hex 字段一律**小写**，偶数长度 |
| hex 解码 | 拒绝奇数长度、拒绝非 hex 字符、解码后长度必须与 Profile 要求一致 |
| 密码学 transcript 内的整数 | **显式大端**（[D-004](../../decisions/0003-冻结决策.md)） |
| 帧头整数 | **小端**（传输层，非密码输入） |

> 现有实现中 transcript 用大端、帧 AAD 用主机本地序，同一字段两种字节序
> （[0002](../../decisions/0002-差异清单.md) §2 S1）。VLP 统一为大端。

## 6. 域标签与摘要构造

所有跨用途的声明摘要使用**域隔离**标签，构造形式统一：

```
digest = SHA256d( domainLabel(UTF-8, 无 NUL)
                || 0x00
                || field₁ || separator
                || field₂ || …
                || fieldₙ )
```

- `0x00` 只作**分隔符**，出现在标签之后、以及两个相邻文本字段之间；
  整个构造的**末尾不加** `0x00`。各 Profile 的摘要表逐字节给出，字段边界无歧义。
- 字节串字段原样拼接，不补终止符。
- 固定长度整数按 Profile 摘要表指定宽度与大端。
- **SHA256d = SHA256(SHA256(x))**，用于 secp256k1 签名输入；仅 SHA-256 的场景显式标注。

域标签清单见 [spec/security/01-密码套件.md](../security/01-密码套件.md) §4。

## 7. 一致性验证

`VLP-CBOR-1` 的实现必须通过 `test-vectors/cbor/` 的全部向量，
包括正向量（逐字节期望输出）与负向量（缺字段/乱序/重复/超限/超深/尾随字节）。
只通过正向量的实现不算合规。
