# 04 握手与链路

> VLP 0.1 Draft · 决策见 [D-003](../../decisions/0003-冻结决策.md)、
> [D-004](../../decisions/0003-冻结决策.md)、[D-018](../../decisions/0003-冻结决策.md)。
> 密码原语细节见 [spec/security/01-密码套件.md](../security/01-密码套件.md)。

## 1. 建立流程

```
1  版本/能力协商         HELLO / HELLO_ACK
2  临时密钥与随机数交换   X25519
3  派生方向密钥与 nonce   HKDF-SHA256
4  双端显示同一配对码     设备实体确认
5  认证加密连接就绪       PAIR_CONFIRM / PAIR_OK
6  持有权证明             POSSESSION_PROVE / POSSESSION_OK
7  开启会话               业务请求可提交
```

**通过持有权证明之前，设备不接受任何业务 `REQUEST`。**

## 2. HELLO / HELLO_ACK

### 2.1 HELLO（未加密，主机 → 设备）

键序：

| 序 | 键 | 键长 | 类型 | 约束 |
| --- | --- | --- | --- | --- |
| 1 | `hostEph` | 7 | bytes | 恰好 32 |
| 2 | `hostNonce` | 9 | bytes | 恰好 32 |
| 3 | `capabilities` | 12 | array/uint | 主机支持项 |
| 4 | `protocolVersion` | 15 | u32 | **必须 = 1**，否则关闭链路 |
| 5 | `walletGeneration` | 16 | u32 | ≠ 0 |
| 6 | `backendGeneration` | 17 | u32 | ≠ 0 |
| 7 | `hostRunGeneration` | 17 | u32 | ≠ 0 |

键长：`capabilities`(12) < `protocolVersion`(15) < `walletGeneration`(16) <
`backendGeneration`(17) = `hostRunGeneration`(17)；同为 17 时
`backendGeneration` < `hostRunGeneration`。

未知键**一律拒绝**。`protocolVersion` 缺失或 ≠ 1 → `version-mismatch`，
**不隐式降级**。

> 键名使用完整名称（`walletGeneration`/`backendGeneration`），
> 消除现有实现中 HELLO 与 REQUEST 用不同缩写的问题
> （[0002](../../decisions/0002-差异清单.md) §2 S4）。

### 2.2 HELLO_ACK（未加密，设备 → 主机）

键序：

| 序 | 键 | 键长 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | `state` | 5 | u32 | 设备状态（§2.3） |
| 2 | `language` | 8 | text | `en`/`zh-Hans`/`zh-Hant`/`zh-Hk`/`ja` |
| 3 | `deviceEph` | 9 | bytes | 32 |
| 4 | `publicKey` | 9 | bytes | 33，业务压缩公钥 |
| 5 | `deviceNonce` | 11 | bytes | 32 |
| 6 | `deviceRunId` | 11 | u32 | ≠ 0 |
| 7 | `capabilities` | 12 | array of u32 | §2.4 |
| 8 | `connectionId` | 12 | u32 | 本条连接标识 |
| 9 | `firmwareBuildId` | 15 | text | 固件构建标识 |
| 10 | `pairingRequired` | 15 | bool | 是否需配对确认 |
| 11 | `protocolVersion` | 15 | u32 | = 1 |
| 12 | `supportsLockedInfo` | 18 | bool | 锁定时是否开放最小信息 |

### 2.3 设备状态

| 值 | 状态 | 允许的操作 |
| --- | --- | --- |
| 0 | `uninitialized` | **仅**迁移专用连接（§6） |
| 1 | `locked` | 最小信息 + 配对；**不允许**业务签名 |
| 2 | `unlocked` | 配对与持有权证明 |
| 3 | `session` | 全部已声明能力 |
| 4 | `pending-request` | 同 3，另有待用户确认的请求 |
| 5 | `migration` | 迁移专用操作 |

### 2.4 能力声明

`capabilities` 数组元素为 `u32`，取值
`(category << 8) | operation`：

| 类别 | 值 | 操作 |
| --- | --- | --- |
| SYSTEM | `0x00` | `info`(0x01) |
| IDENTITY | `0x01` | `prove`(0x11)、`authorize`(0x12) |
| TRANSACTION | `0x02` | `p2pkh-sign`(0x21) |
| CHANNEL | `0x03` | `public-message`(0x31)、`hash-request`(0x32)、`private-message`(0x33)、`seal`(0x34)、`open`(0x35) |
| LOCAL_SECRET | `0x04` | `seal`(0x41)、`open`(0x42) |
| CONTENT | `0x05` | `attest-digest`(0x51) |
| EVIDENCE | `0x06` | `receive`(0x61) |
| MIGRATION | `0x07` | `import`(0x71)、`export`(0x72)、`status`(0x73) |

**能力表只列真实可执行且有向量的操作**（[D-009](../../decisions/0003-冻结决策.md)）。
0.1 的 VLP 参考实现在 `evidence.*` 与 `migration.*` 未冻结前**不声明**这些能力。

## 3. transcript 与密钥派生

### 3.1 transcript

```
transcript = SHA256(
    "vlp:handshake:v1"            UTF-8, 16 字节, 无 NUL
 || 0x01                          protocolVersion, 1 字节
 || hostNonce                     32
 || deviceNonce                   32
 || hostEphemeral                 32
 || deviceEphemeral               32
 || deviceRunId                   u32 大端
 || hostRunGeneration             u32 大端
 || walletGeneration              u32 大端
 || backendGeneration             u32 大端
 || publicKey                     33
)
```

共 **194 字节**输入（16 + 1 + 32×4 + 4×4 + 33），`SHA256` 单次（非双次）。
所有整数**大端**（[D-004](../../decisions/0003-冻结决策.md)）。

> 版本字节参与哈希。现有文档遗漏了它
> （[0002](../../decisions/0002-差异清单.md) §3 D1）。

### 3.2 方向密钥与 nonce

```
shared      = X25519(deviceEphemeralPriv, hostEphemeral)              32
c2sKey      = HKDF-SHA256(ikm=shared, salt=transcript,
                          info="vlp:link:c2s:key:v1",  L=32)
c2sBaseNonce= HKDF-SHA256(ikm=shared, salt=transcript,
                          info="vlp:link:c2s:nonce:v1", L=12)
s2cKey      = HKDF-SHA256(ikm=shared, salt=transcript,
                          info="vlp:link:s2c:key:v1",  L=32)
s2cBaseNonce= HKDF-SHA256(ikm=shared, salt=transcript,
                          info="vlp:link:s2c:nonce:v1", L=12)
```

**两个方向不得共用密钥或同一条 nonce 链。**
salt 为 32 字节 `transcript`（非空，不使用默认盐）。

### 3.3 配对码

```
h      = SHA256("vlp:link:pairing:v1" || transcript)      51 字节输入, 单次 SHA-256
v      = (h[0] << 16) | (h[1] << 8) | h[2]               24 位大端
code   = 6 位十进制数字串, 最高位在前：code = format("%06d", v mod 10^6)

6 位数字码的有效熵约 **19.9 位**，这是数字码本身的固有限度。
不通过增加位数或改用更短的码来暗示更强的配对强度；
配对安全由「设备实体确认 + transcript 绑定」保证，不依赖穷举猜测。
```

设备屏幕显示 `code`；用户在设备上**实体确认**后，主机才发 `PAIR_CONFIRM`。

### 3.4 绑定要求

| 要求 | 内容 |
| --- | --- |
| 配对码 | 绑定 transcript（含双方 nonce、临时公钥、世代、公钥） |
| 防降级 | `protocolVersion` 进入 transcript 与 AAD |
| 防跨连接复用 | 密钥与 nonce **不跨** `deviceRunId`/`connectionId`/会话复用 |
| 连接重建 | 新 `deviceRunId`、新临时密钥、新 `connectionId`；旧会话、旧队列、旧结果全部失效 |

## 4. PAIR_CONFIRM / PAIR_OK

| 消息 | 键序 | 值 |
| --- | --- | --- |
| `PAIR_CONFIRM` | map(1) | `code`(4) text，恰好 6 字符 |
| `PAIR_OK` | map(2) | `paired`(6) bool = true；`protocolVersion`(15) u32 = 1 |

设备必须已收到用户实体确认才接受 `PAIR_CONFIRM`。

## 5. 持有权证明

### 5.1 主机发送

`POSSESSION_PROVE`：map(1)，`challenge`(9) bytes 恰好 32。

### 5.2 设备构造的声明摘要

```
statementDigest = SHA256d(
    "vlp:possession:v1"        UTF-8, 17 字节
 || 0x00
 || publicKey                 33
 || deviceRunId               u32 大端
 || hostRunGeneration         u32 大端
 || sessionId                 u32 大端
 || challenge                 32
)
```

共 **95 字节**输入（17 + 1 + 33 + 4×3 + 32），`SHA256d` = SHA256(SHA256(x))。

**设备构造域隔离摘要，不直接签主机给的 challenge。**
若直接签 challenge，主机即可把交易摘要当 challenge 换走一个与
`tx.p2pkh-sign` 同等有效的签名，而该交易从未在设备屏幕上出现过。
域隔离让这类跨操作复用不成立。

### 5.3 设备响应

`POSSESSION_OK`：map(5)，键序：

| 序 | 键 | 键长 | 类型 |
| --- | --- | --- | --- |
| 1 | `challenge` | 9 | bytes 32（原样回显） |
| 2 | `publicKey` | 9 | bytes 33 |
| 3 | `sessionId` | 9 | u32 |
| 4 | `signature` | 9 | bytes，strict DER |
| 5 | `statementDigest` | 15 | bytes 32 |

签名：ECDSA secp256k1，RFC 6979 确定性 nonce，low-S，strict DER。
主机用业务公钥对 `statementDigest` 验签，**并核对公钥等于预期值**。

### 5.4 验签失败

`wrong-key`。链路保持加密但**不开启会话**，业务请求一律拒绝。

## 6. 未初始化与锁定

| 设备状态 | 允许 |
| --- | --- |
| `uninitialized` | **仅**迁移专用连接：实体配对完成后接收导入 |
| `locked` | §2 的最小信息 + 配对 |

**未初始化设备不因「必须先有 Key」而无法导入**：
迁移连接在实体配对后即可接收导入，导入完成才证明持有业务身份；
**不以生成新 Key 代替迁移**。普通业务在未初始化状态下仍需身份验证。

设备**锁定幂等**，重复锁定不改变状态。

## 7. 连接与世代规则

| 规则 | 内容 |
| --- | --- |
| 控制连接 | 设备只允许**一条**合法控制连接 |
| 会话隔离 | 多 App 会话仍只有一个控制连接；会话隔离与关闭必须有**设备可检查的绑定** |
| 世代校验 | 每条业务请求的三个主机世代、`sessionId`、`sessionEpoch` 必须与建会话时**完全相同** |
| 断开 | 断线、失活、锁定、重启、迁移 → 清空持续决定、清队列、使旧结果交付失效 |
| 迟到响应 | 旧 `connectionId`/`sessionId` 的响应**不进入**新身份或新会话 |

## 8. 中止与恢复

`ABORT`：map(1)，`reason`(6) u32，取 `LinkError` 值。

| 原因 | 含义 |
| --- | --- |
| 0 | none |
| 1 | `version-mismatch` |
| 2 | `bad-hello` |
| 3 | `decrypt-failed` |
| 4 | `replay` |
| 5 | `unauthorized` |
| 6 | `timeout` |

**任何 `ABORT`、认证失败或失活超时都必须中止连接并清空全部密钥材料**，
回到待握手状态。**禁止**在失败后继续使用错位的 nonce 链
（[0002](../../decisions/0002-差异清单.md) §1 B4）。

主机侧恢复方式：**重新握手**。不提供链路内重同步。
