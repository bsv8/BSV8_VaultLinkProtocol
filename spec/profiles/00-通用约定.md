# 00 Profile 通用约定

> VLP 0.1 Draft · 本文件定义所有 Profile 共用的字段结构、承诺覆盖规则、
> 审核对象与结果信封。各 Profile 只定义自己的字段、语义与兼容规则。

## 1. 操作请求体

Profile 请求体是 `VLP-CBOR-1` map，键序（长度优先，再字节序）：

| 序 | 键 | 键长 | 类型 | 必填 |
| --- | --- | --- | --- | --- |
| 1 | `op` | 2 | text | **是，且必须是第一个键** |
| 2 | `opVersion` | 9 | u32 | 是 |

其后是各 Profile 自己的字段，**继续按长度优先再字节序严格递增**。
未知键、重复键、乱序键一律 `invalid-request`。

| 项 | 规则 |
| --- | --- |
| `op` | 已登记的操作名，长度 ≤ 31 字节；未登记 → `unsupported` |
| `opVersion` | 必须等于该 Profile 声明的版本；否则 `invalid-request` |
| 必填缺失 | `invalid-request` |
| 未知字段 | `invalid-request`（不允许夹带降级字段） |
| 文本字段 | 必须良构 UTF-8，长度上限见各 Profile |

## 2. 承诺覆盖对象

各 Profile 定义 `commitObject`——该 Profile 下"设备可独立重算的规范对象"。

```
requestCommitment = SHA256d(
    "vlp:commit:v1" || 0x00
  || profileId || 0x00 || profileVersion(u8)
  || commitObject（VLP-CBOR-1 编码）
)
```

`commitObject` 必须覆盖（按 Profile 逐项列明）：

1. **实际操作**——将被签名/加密/解封的字节本身；
2. **安全相关证据**——网络、金额、前序、输入归属、接收公钥、范围参数；
3. **显示内容**——设备将展示的关键字段。

**主机不得挑选覆盖字段。** 设备按本表重算并比较。

## 3. grantScope 提取

各 Profile 定义如何从请求提取 `grantScope`
（见 [05-承诺与授权.md](../core/05-承诺与授权.md) §3）。

| Profile | 持续允许 | 提取字段 |
| --- | --- | --- |
| Identity | **不可** | — |
| BSV P2PKH | **不可** | — |
| Channel | 同对端/协议/方向 | `peerPublicKey`、`protocolId`、`direction` |
| Local Secret | 同 scope | `scope` |
| Content | **不可** | — |
| Migration | **不可** | — |
| Evidence | 已退出当前范围：业务说明归 Keymaster | — |

## 4. 结果信封

Profile 结果是 `VLP-CBOR-1` map，键序严格递增。

| 通用字段 | 键长 | 类型 | 说明 |
| --- | --- | --- | --- |
| `publicKey` | 9 | bytes 33 | 产生结果的业务公钥（签名类操作必含） |
| `signatureFormat` | 15 | text | `der-strict-lows` 或 `compact-lows` |

签名类结果**必须**回报所用签名格式；不得让主机猜测。

## 5. 结构化审核对象

设备在询问用户前生成审核对象。**关键字段来自设备验证与固定模板**；
主机长说明只是标注来源的辅助内容，**不替换模板**。

| 字段 | 说明 |
| --- | --- |
| 操作 | 稳定操作标识 |
| 完整对象标识 | 完整公钥、地址、协议、对端（**不截断**关键标识） |
| 金额或权限 | 交易金额、导出/擦除的权限范围 |
| 范围 | 持续授权将覆盖的范围 |
| 来源状态 | 哪些是设备已验证、哪些是主机声称 |
| 主要风险 | 设备生成的风险提示 |
| **不包含的权限** | 明确列出本次**不会**授予的能力 |

## 6. 交互契约

| 规则 | 内容 |
| --- | --- |
| 确认绑定 | 用户确认必须绑定 `requestId`、承诺与 `decisionRevision` |
| 关键摘要 | **必须**经过并明确确认 |
| 重大警告 | **必须**经过并明确确认 |
| 可选长文 | **无需**滚到底 |
| 换页 | 先松键；确认进度可见；拒绝与锁定可达；返回保留阅读位置 |
| 完整对象 | 可查看完整对象（不截断） |
| 内容冻结 | 阅读开始后内容冻结；安全相关变更**必须重新确认** |
| 不确定即拒绝 | 缺字、控制字符或超限导致关键内容不确定时**拒绝**，不得截掉风险继续授权 |

具体三按钮布局、字号、语言与字体由设备实现，不属本规范。

## 7. Profile 版本与能力

| 项 | 规则 |
| --- | --- |
| 版本 | 各 Profile 独立版本（[01-术语与版本](../core/01-术语与版本.md) §4） |
| 能力声明 | 只列真实可执行且有向量的操作（[D-009](../../decisions/0003-冻结决策.md)） |
| 未冻结 Profile | **不出现在已支持集合**；请求返回 `unsupported` |
| 未知脚本/算法/网络 | 明确拒绝，不降级 |
