# 01 USB Serial 传输

> VLP 0.1 Draft · 决策见 [D-016](../../decisions/0003-冻结决策.md)、
> [D-019](../../decisions/0003-冻结决策.md)。

## 1. 范围

VLP 0.1 **只**定义 USB Serial 传输（主机侧 Web Serial）。
不增加 HID、BLE、网络或 FIDO/CTAP2。

Core 与字节传输**解耦**：Core 以字节流进出，不感知 USB。
未来传输有独立规格、独立能力声明、独立验收，**不默认为已支持**。

## 2. 字节流而非消息

| 规则 | 内容 |
| --- | --- |
| 读入边界 ≠ 帧边界 | 禁止把一次 read 当成一帧 |
| 断包 | 一帧可跨多次 read |
| 粘包 | 一次 read 可含多帧 |
| 噪声 | 帧解析器必须重同步（见 [03-帧与消息.md](../core/03-帧与消息.md) §2.3） |
| 分配 | 不按主机自报长度分配内存 |

## 3. 单帧（0.1 无分片）

**VLP 0.1 不支持分片。** 超限**明确拒绝**，不截断、不静默丢弃关键内容。

| 限额 | 值 |
| --- | --- |
| `MAX_FRAME_PAYLOAD` | 1024 字节 |
| `MAX_MESSAGE`（明文业务消息） | 896 字节 |
| 接收缓冲 | 1039 字节 |

### 3.1 容量实测

首批 Profile 样本的编码后尺寸由 `tools/refgen` 生成、写入
`test-vectors/limits/frame-capacity.json`，并由 `conformance/` 复核。

结论（`spec/core/03-帧与消息.md` §5）：**单帧上限不能承载**现有实现声明的
`rawTx ≤ 8192` / `channel message ≤ 512` / `local-secret plaintext ≤ 4096`。
各 Profile 字段上限已按 896 字节收敛，超限返回 `invalid-request`。

**不声称**可传内部大缓冲允许的大交易或长文。

### 3.2 分片（后续范围）

分片需定义：分片 ID 与序号、重组队列与上限、认证覆盖分片关联、
中断与重连时丢弃旧材料。作为传输独立规格的后续范围。

## 4. 权限与连接

| 规则 | 内容 |
| --- | --- |
| Web Serial 权限 | 只在**合法用户交互上下文**请求（Window） |
| Worker | 通过适配桥使用协议客户端；桥由宿主实现，不属 VLP |
| 控制连接 | 设备只允许**一条**合法控制连接 |
| 主机侧桥 | 主机允许多个应用会话，但只有一个控制桥持有传输 |
| 失活 | 通过可验证连接存活与超时判定；**不能凭 USB 供电持续就保留授权** |

Web Serial 权限请求、`navigator.serial` 的可用性与 VID/PID 过滤**不属** VLP 规范，
属传输适配实现。

## 5. 失活与清理

| 触发 | 处置 |
| --- | --- |
| 失活超时（8000 ms 无有效帧） | 清空持续决定、清队列、清密钥材料、锁定 |
| 主机主动关闭 | 同上 |
| 断线 | 同上；主机须重新握手 |
| 设备重启 | 新 `deviceRunId`；全部旧会话与队列失效 |

**旧 `connectionId` 的迟到响应不进入新身份或新会话。**

## 6. 传输层不做的事

传输层**不**提供：

- 业务语义判断（属 Core/Profile）；
- 授权决策（属设备侧授权层）；
- App origin、设备厂商或交易安全的证明。

**USB 只搬运字节。** 设备编号、`VID:PID`、主机名称、域名或主机自述 `verified`
都不构成身份凭据或安全证明。
